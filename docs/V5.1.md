# v5.1 beta

The beta adds optional Deepgram streaming recognition, Hindi and Hindi/English modes, Hindi/Hinglish PC commands, Hindi neural reply voices, Spotify playback and app navigation, numbered window selection, guided microphone setup, native audio-device recovery and signed in-app updates. Stable v5 remains available while the beta receives hands-on testing.

## Hindi and listening

Select **Settings → Listening language → hi-IN**, or **auto** for Hindi/English with Groq or Deepgram. Deepgram requires a separate account/key; requests opt out of its model-improvement program and account charges may apply. Auto service without working Groq access falls back to Google Hindi when automatic language detection is selected.

The bundled local model and spoken interruption detector are English-only; use English “stop” or Escape during playback. Hindi response text selects Swara for FRIDAY or Madhur for ALFRED. Groq expressive speech is English-only, so Hindi text uses Edge. Without internet or an installed Hindi Windows voice, the complete response remains on screen.

Wake audio remains local. A missing local model never starts online standby recognition. Use the new input meter while speaking, and calibrate while quiet. The default pause is adjustable; increase it if your Hindi phrases are being cut short.

## Commands

- “Spotify kholo”, “नोटपैड खोलो”, “आवाज़ कम करो”, “वॉल्यूम ४० प्रतिशत करो”.
- “स्पॉटिफाई में गाना चलाओ”, “Spotify mein agla gana”, “play in Spotify”, “pause in Spotify”, “next track in Spotify”.
- “Search Spotify for jazz”, “play first result in Spotify”. The latter requires a unique accessible Songs section and Play button. It refuses to guess if Spotify does not expose them.
- “Go to library in Spotify”, “go to queue in Spotify”, “go to liked songs in Spotify”.
- “Go back in Chrome”, “next tab in Edge”, “scroll down in File Explorer”. Navigation shortcuts require the intended window to retain focus.
- “List windows in Chrome”, then “focus Chrome window 2” or “close Chrome window 2”. Window numbers expire after 60 seconds; closing still permits unsaved-work prompts.

Support depends on each app exposing accessible controls. These commands do not provide unrestricted control of every app. A worker that stalls is terminated after six seconds; it cannot later resume queued clicks. Cancellation does not undo an action already accepted by an app.

Spotify playback first uses its own Windows media session, including while minimized. It never controls the global player or a browser playing music. Duplicate Spotify sessions require selection in Spotify. Play/pause checks the current state instead of toggling blindly; next/previous reports whether Spotify accepted the request. The accessibility fallback and first-result selection depend on Spotify exposing its controls, which some builds do not. Library/queue navigation uses Spotify's shortcuts and reports the request without claiming the resulting view was verified.

## Installation, updates and recovery

Use the beta installer from the repository's Releases page. The ordinary stable updater excludes prereleases. The installer includes Python and the small English wake model. The portable EXE never downloads it automatically; installation is an explicit Settings action.

On first launch, enter your own Groq API key and select **Verify key & finish**. Setup keeps the key hidden and saves it in personal app data only after the connection succeeds. **Use limited offline mode** completes setup without a key for supported local PC commands, notes and timers; open-ended AI conversation remains unavailable.

Updates verify the original publisher's pinned RSA key, signed manifest and installer hash. They recheck the file immediately before launch. A settings checkpoint is saved; API keys and conversations remain in personal app data. An incomplete update can be retried, and **Restore settings from before update** restores the checkpoint. This is not automatic rollback of the app binary.

The manifest signatures preserve the existing `lkghost327-afk` publisher identity. Windows Authenticode is separate. See [cross-PC verification](../OWNERSHIP.md), [validation and remaining gates](VALIDATION-v5.1.md), and [the execution plan](ROADMAP-v5.1.md).
